## Язык программирования

### Синтаксис

Синтаксис языка описывается расширенной формой Бэкуса-Наура (EBNF):

```ebnf
program        ::= stmt* EOF

stmt           ::= var_decl | if_stmt | while_stmt | func_def | return_stmt
               |   print_stmt | printnum_stmt | printu_stmt | putc_stmt
               |   irq_def | assign_stmt | expr_stmt

var_decl       ::= "var" IDENT ("[" NUM "]")? ("=" expr)? ";"
if_stmt        ::= "if" "(" expr ")" block ("else" block)?
while_stmt     ::= "while" "(" expr ")" block
func_def       ::= "func" IDENT "(" param_list? ")" block
return_stmt    ::= "return" expr? ";"
irq_def        ::= "irq" IDENT block
assign_stmt    ::= lhs "=" expr ";"
expr_stmt      ::= expr ";"

print_stmt     ::= "print" "(" expr ")" ";"
printnum_stmt  ::= "printnum" "(" expr ")" ";"
printu_stmt    ::= "printu" "(" expr ")" ";"
putc_stmt      ::= "putc" "(" expr ")" ";"

block          ::= "{" stmt* "}"
param_list     ::= IDENT ("," IDENT)*
lhs            ::= IDENT | IDENT "[" expr "]"

expr           ::= or_expr
or_expr        ::= and_expr ("||" and_expr)*
and_expr       ::= eq_expr ("&&" eq_expr)*
eq_expr        ::= cmp_expr (("==" | "!=") cmp_expr)*
cmp_expr       ::= add_expr (("<" | ">" | "<=" | ">=") add_expr)*
add_expr       ::= mul_expr (("+" | "-") mul_expr)*
mul_expr       ::= unary_expr (("*" | "/" | "%") unary_expr)*
unary_expr     ::= ("-" | "!") unary_expr | primary
primary        ::= NUM | STR | CHR | IDENT ("(" arg_list? ")")? | IDENT "[" expr "]" | "(" expr ")"
arg_list       ::= expr ("," expr)*
```

### Семантика

* **Стратегия вычислений:** аппликативная (eager) — аргументы вычисляются до вызова функций. Выражения вычисляются слева направо.
* **Области видимости:** статическая (лексическая). Глобальные переменные доступны везде. Локальные переменные и аргументы доступны внутри тела функции.
* **Типизация и литералы:**
  * Типизация нестрогая статическая, базовый тип — 32-битное знаковое целое число. Булевы значения: `0` = ложь, не `0` = истина.
  * *Целочисленные литералы*: `42`, `0`.
  * *Символьные литералы*: `'A'`, `'\n'`, хранятся как целое число (код символа).
  * *Строковые литералы*: `"hello\n"`. Поддерживается тип `pstr` (Pascal string).

## Организация памяти

Модель памяти: **Гарвардская архитектура** (раздельные памяти команд и данных). 
* Размер машинного слова: 32 бита. 
* Адресация: пословная. 
* Тип памяти: однопортовая.
* Доступные программисту регистры: общего назначения (R0-R5), FP (указатель кадра), SP (указатель стека).

```text
       Registers
+------------------------------+
| R0 (ACC), R1-R5, FP, SP      |
+------------------------------+

       Instruction memory (4096 words)
+------------------------------+
| 00  : irq_handler instruction|
|    ...                       |
| i   : built-in functions     |
| j   : user functions         |
|    ...                       |
| n   : entry point (main)     |
+------------------------------+

          Data memory (4096 words)
+------------------------------+
| 00  : global variable 1      |
| 01  : array A[0]             |
|    ...                       |
| c   : constants / strings    |
|    ...                       |
| 4093: STACK_START (grows down|
| 4094: INPUT_DATA (Mapped IO) |
| 4095: OUTPUT_DATA (Mapped IO)|
+------------------------------+
```

**Отображение сущностей:**
1. **Литералы и константы:** Целочисленные литералы кодируются непосредственной адресацией в инструкциях (например, `LDI`). Константы, к которым нужен доступ по адресу (для операций `ADDM`, `CMPM`), размещаются в статической памяти данных с дедупликацией. Строки (`pstr`) сохраняются в статической памяти данных: первое машинное слово — длина, затем упакованные по 4 символа слова.
2. **Переменные:** Глобальные и статические переменные отображаются на адреса в секции данных. Локальные вычисления происходят на регистрах, при нехватке регистров сохраняются на стек.
3. **Массивы:** Занимают непрерывную область памяти данных, доступ вычисляется через базовый адрес + смещение (`LD_IND` / `ST_IND`).
4. **Инструкции и процедуры:** Инструкции хранятся в памяти команд. Процедуры вызываются через инструкцию `CALL` (аргументы передаются через стек). Внутри функции параметры лежат по смещению от `FP`. Возврат — `RET`, результат в `R0`.
5. **Прерывания:** Обработчик прерывания (если определён) сохраняется в начало памяти команд. Прерывания запрещаются (вложенность не поддерживается) аппаратно до вызова `IRET`.

## Система команд

**Особенности процессора:**
* Архитектура: **CISC** (переменная длина команд (1, 2 или 1+N слов), память-регистр операции, наличие многословной инструкции расчета полинома `POLY`).
* Устройство ввода-вывода: **Memory-mapped** порты на адресах 4094 (ввод) и 4095 (вывод). Механизм получения данных — **Trap** (прерывания от устройства).
* Поток управления: аппаратный стек (SP, FP), инструкции `CALL` / `RET` для подпрограмм, флаги `Z`, `N`, `C`, флаг разрешения прерываний `I`.

**Способ кодирования инструкций:**
Инструкции кодируются в 32-битные слова. 
* Однословная команда: `[opcode: 8 bit] [reg1: 4 bit] [reg2: 4 bit] [imm16: 16 bit]`.
* Двухсловная команда: Слово 0 (как выше), Слово 1: `[imm32: 32 bit]`.
* Инструкция `POLY` (переменной длины): Слово 0 содержит кол-во пар `N` в поле `imm16`. За ним следуют `N` машинных слов, содержащих `[addr_coef: 16 bit][addr_var: 16 bit]`.

**Набор инструкций и количество тактов:**

| Мнемоника | Формат | Тактов | Описание |
|---|---|---|---|
| `hlt`, `sti` | 1 слово | 2 | Управление состоянием процессора |
| `jmp`, `jz`, `jnz`, `jg`, `jl`, `jge`, `jle`, `jc` | 1 слово | 2 | Переходы (PC ← addr при выполнении условия) |
| `call addr` | 1 слово | 3 | Вызов подпрограммы (push PC, PC ← addr) |
| `ret` | 1 слово | 3 | Возврат (pop PC) |
| `iret` | 1 слово | 5 | Возврат из прерывания (pop flags, pop PC, I ← 1) |
| `mov`, `ld`, `st`, `ld_ind`, `st_ind` | 1 слово | 2 | Перемещение данных (регистры, память) |
| `push`, `pop` | 1 слово | 3 | Работа со стеком |
| `ldi`, `addi`, `subi`, `muli`, `cmpi` | 2 слова | 2 | Операции с 32-битными константами (`imm32`) |
| `add`, `sub`, `mul`, `div`, `mod`, `cmp`, `and`, `or`, `not`, `inc`, `dec` | 1 слово | 2 | Арифметика и логика (регистр-регистр) |
| `addm`, `subm`, `mulm`, `cmpm`, `divm`, `modm`, `andm`, `orm` | 1 слово | 2 | CISC операции (регистр-память) |
| `poly rd, N, (c,x)...` | 1+N слов | 3+3N| CISC инструкция. Аккумулирует `rd += c*x` |

## Транслятор

Консольное приложение для компиляции исходного кода в бинарный файл.

**Интерфейс командной строки:**
`python -m src.translator <source.alg> <output.bin>`

**Входные данные:** 
* Текстовый файл с исходным кодом на разработанном языке (аргумент 1).
**Выходные данные:** 
* Бинарный файл скомпилированной программы (аргумент 2). Дополнительно генерируется ассемблерный листинг (`.asm`) и текстовое представление AST дерева (`.ast`) для отладки.

**Принципы работы транслятора:**
1. *Лексический анализ (Lexer):* Разбиение потока символов на токены.
2. *Синтаксический анализ (Parser):* Построение Абстрактного Синтаксического Дерева (AST) методом рекурсивного спуска.
3. *Генерация кода (CodeGen):* 
   * Выделение памяти под глобальные переменные и строковые литералы (секция данных).
   * Определение используемых встроенных функций и генерация их кода (Dead Code Elimination на уровне библиотек).
   * Генерация машинных инструкций путем обхода AST-дерева. Промежуточные результаты вычисляются в `R0`. Поддержка CISC-инструкций выполняется путем сворачивания ветвей дерева (например: узел бинарной операции умножения переменных сворачивается в `MULM` или `POLY`).
   * Разрешение меток (Fixups) и формирование финального массива бинарных инструкций.

## Модель процессора

Консольное приложение, симулирующее выполнение бинарного файла на процессоре.

**Интерфейс командной строки:**
`python -m src.machine <binary.bin> [input_schedule.txt]`

**Входные данные:**
* Имя файла машинного кода (аргумент 1).
* Имя файла расписания имитации ввода в процессор (аргумент 2, формат: `<такт> <символ>`).
**Выходные данные:**
* Вывод данных из процессора в `stdout`.
* Журнал состояний процессора по тактам в терминале (Tick, PC, Флаги, Регистры, Инструкция).

## Тестирование

**Краткое описание тестов:**
Интеграционное тестирование реализовано через Golden-тесты. Эталонные тесты находятся в папке `tests/golden` и включают:
* `in_source`: Исходный код
* `in_stdin`: Ввод программы
* `out_code_hex`: Скомпилированный код
* `out_ast`: Транслированное AST
* `out_stdout` и `out_log`: Стандартный вывод программы и журнал работы процессора.

Запуск тестов в CI: `pytest tests/test_golden_yaml.py -v`.

**Golden тесты алгоритмов:**
1. `hello` — печать "Hello World!".
2. `cat` — эхо-вывод данных, поданных через ввод (используются прерывания `trap`).
3. `hello_user_name` — запрос имени и вывод приветствия через `trap` I/O.
4. `sort` — пузырьковая сортировка массива.
5. `double_prec` — арифметика двойной точности с использованием функции возврата переноса `carry()`.
6. `alg1` — Euler problem 4: Поиск наибольшего палиндрома, полученного умножением двух трехзначных чисел.
